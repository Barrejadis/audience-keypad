# Virtual Key Device — Security

**Technical specification · Status:** Draft · **Normative language:** the key words MUST, MUST NOT, SHOULD, and MAY are to be interpreted as in RFC 2119.

Covers: cross-cutting security requirements. Applies to [The keyboard](01-keyboard.md) (sessions, label escaping) and [The probe](02-probe.md) (admin auth, language interpreter).

- **The closed language is the security boundary of (c).** No loops, no recursion, no I/O, and hard caps on program size and state width mean a submitted program cannot loop, spawn, read files, or exhaust memory beyond a fixed bound. The interpreter MUST parse to an AST; `eval()`-style execution of submitted text is forbidden.
- **Admin password:** hardcoded SHA-256 hash constant (`ADMIN_HASH`), compared with `hash_equals` (constant-time); transported only in a POST body. Alias management actions (create, rebind, delete — *Aliases*) are admin actions like the rest of (c) and share this authentication. Alias definitions are admin-authored, rendered with the same escaping as a direct (a) entry; the `409` reroute and `404` unknown-alias responses carry no reflected user-controlled content.
- **(b) is unauthenticated by design** (anonymous users); its exposure is bounded by input validation (a key id must be in the user's own key set; an undo requires a limited device and can only remove strokes from the user's own log), the per-user keystroke cap (`L` on a limited device, `MAX_STROKES` otherwise), and TTL expiry.
- **Session hardening (impersonation resistance).** User identity is the PHP session id: a 128-bit random cookie value, so guessing is infeasible and the only practical attacks are cookie theft and session fixation. The server MUST set `session.use_strict_mode = 1` (rejects attacker-chosen session ids, killing fixation), `session.cookie_httponly = 1` (keeps the cookie away from scripts), `session.cookie_samesite = "Lax"` (blocks cross-site POSTs to (b)), and `session.cookie_secure = 1` when served over HTTPS. Labels are URL-supplied and MUST be HTML-escaped when rendered (page rendering requirements: *The keyboard*), so a crafted `keys=` link cannot XSS a victim's session. Note the payoff of impersonation is inherently low: it only lets an attacker pollute one anonymous user's keystroke log.
- **Accepted risks / trade-offs:** the label registry grows with the number of distinct labels ever served (tiny entries, acceptable); sessions identify browsers, not people; APCu is single-server only.
